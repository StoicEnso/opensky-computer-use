OpenSky 1.1.0 — investigation and verification
Created 17 October 2026 (Europe/London)

DELIVERED
An independent MIT-licensed macOS helper with Accessibility inspection and actions,
window and primary-display screenshots, Apple Vision OCR, keyboard/mouse input,
clipboard paste, window management, requested AppleScript/JXA, and named animated
pointers. Interfaces: local stdio MCP, CLI, and JavaScript SDK. No model/provider API
is required by the engine. Any connected model has its own cost and permissions.

The existing local OpenSky prototype was preserved and copied into a separate Git
project before changes. The original prototype and Randos checkout were not edited.

RESEARCH QUESTIONS AND EVIDENCE
1. What does the observed Codex interaction loop expose? Answered at interface level.
   The shipped Sky Window API documentation exposes app discovery, state capture,
   indexed and coordinate actions, keys, typing, scrolling, dragging, value changes,
   secondary accessibility actions, paste, and text selection. Its coordinates are
   app-window relative. OpenSky deliberately documents global desktop points instead;
   its SDK is not a drop-in replacement for Sky.

DESIGN LOCK AND IMPLEMENTATION DECISIONS
Primary reference: demonstrated independent pointer, curved motion, directional tilt.
Preserve: click-through overlay, compact readable status label, visible target feedback.
Bounded secondary guidance: the Refero motion reference's fast functional feedback and
macOS Reduce Motion preference. Reduce Motion disables curves and thinking wiggle.
Palette roles: white pointer outline for contrast, sampled accent for halo/highlight;
no decorative full-screen effects. Native system text for labels.
One overlay window per display handles macOS separate Spaces; a single union window
failed visual verification on this Mac and was replaced. Global coordinates account
for displays left/above the primary display and pixels versus points.

CORRECTNESS IMPROVEMENTS
- Authenticated IPv4-loopback control endpoint, no permissive CORS, browser origins
  rejected, owner-only token, bounded HTTP input, no unauthenticated control fallback.
- Serialized native action queue, independently responsive stop/status, menu-bar
  pause/resume/quit and Control+Option+Command+Escape emergency pause.
- Full snapshots with generation-specific indices, expiry, live target validation
  and explicit errors. Full snapshots intentionally replace unsafe index-based diffs.
  No fabricated fallback coordinates or silent desktop capture
  when a requested app-window capture fails.
- Background clicks use supported AXPress only and fail if unavailable. Hybrid input
  verifies foreground target and hit ownership. Background drag fails explicitly.
- Unknown keys/modifiers fail before input; Unicode stays intact; clipboard restoration
  respects the original contents and concurrent changes. Live tests exposed and fixed
  Command remaining latched after shortcuts; literal Unicode text clears modifiers.
  The md paste alias now agrees with the MCP/SDK contract.
- Scripts have cancellation, a timeout and bounded returned output. Stop cannot undo
  completed actions or separately spawned processes.

PERMISSIONS AND LAUNCH IDENTITY — UPDATED 17 OCTOBER 2026
The owner explicitly approved Accessibility and Screen Recording for OpenSky.
Both are enabled and verified by the installed app's native status. The installed
SDK now uses LaunchServices so the app obtains its own permission identity; earlier
direct launches could inherit the parent agent's responsibility chain. A shutdown
and CLI restart retained both permissions. Ad-hoc rebuilds can invalidate an old
permission record even while its Settings switch remains on; removing that old
entry and adding the current app restored access during testing.

LIMITS
This is not a claim of universal app support, superiority over Codex, or autonomous
reasoning. Background PID event delivery varies by app. Default window targeting uses
the app's focused/available window; full-screen capture covers the primary display,
while app-window captures can be on another display. Secure input, system dialogs,
protected content, and OS permissions can limit automation. Named pointer overlays
are concurrent visual indicators; physical input actions are serialized.
Ad-hoc signed local builds are not Developer-ID notarized releases. Other machines
need to build from source and grant their own permissions. No public repository or
package-registry release was created.
